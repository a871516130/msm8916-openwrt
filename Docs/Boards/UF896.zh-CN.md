# UF896 (v1.1)

本页记录 **UF896 v1.1** MSM8916 4G LTE 路由器的 OpenWrt 配置与硬件说明——
目标列表中的第八块板。

> ⚠️ **状态：维护者尚未在真实硬件上验证。** 我们手上没有 UF896 设备。该
> 配置可以构建，其 DTS 与原厂厂商树匹配，但启动、modem 注册和 SIM 选择
> 尚未由我们端到端确认。如果你拥有 UF896，请在 issue 追踪器中反馈结果
> （无论好坏）——参见 [我们需要的反馈](#我们需要的反馈)。

## 构建标识与存储

- 构建别名：`uf896`
- OpenWrt 设备配置：`generic-uf896`
- DTS：`msm8916-generic-uf896`（补丁 867），基于 `msm8916-ufi.dtsi`
- Compatible：`uf896,v1.1`
- eMMC：4 GB 级别（与 `ufi003` 相同）——使用构建默认的 GPT，
  `flash.sh` 在刷写时读取实际容量，因此不匹配只会留下少量未使用空间
- 恢复分区：**无**（15 分区布局）
- 电池：**无**（无电池的 UFI 系列棒）

## Reset / failsafe 按键

- GPIO **35**，**低电平有效，上拉** —— UF02 / HMUF02-V5 / UFI001B 系列的
  接法（`button_default` 引脚 `gpio35` + `gpio107`）。
- Failsafe 模式由 diffconfig 启用（7 秒 preinit 窗口，preinit USB gadget 上
  的 `192.168.10.1`）——参见 [Failsafe](../Failsafe/README.md)。
  **未在该板上实机验证。**
- 提醒：≥5 秒的长按如果*错过*了 7 秒窗口，会对设备执行恢复出厂设置。

## SIM

UF896 **不**通过 AP 侧 GPIO 进行 SIM 选择。默认选中卡槽 1，无需用户态
协助——插在卡槽 1 中的卡在原厂镜像上即可被检测并注册。

厂商固件也接受 `AT+SIMSEL=0,1,1,1`（原厂 `sim1.sh`），但该途径在
OpenWrt 下**不可用**：`mmcli --command` 要求 ModemManager 以 `--debug`
运行，而镜像并未这样做，且 QMI 插件也不会为它保持一个 AT 端口打开。先前的
`luci-app-uf896-simsel` 包（在 r5 中移除）包装了该命令，但从未真正生效过。
如果将来需要选择卡槽 2，受支持的途径是 `qmicli --uim-switch-slot=<n>`——
在该固件上未测试。

不存在 `sim-presence` / `sim_hotplug` GPIO hog，因此**SIM 热插拔在该板上
未测试**。参见 [SIM Hot-Swap](../SIM_HOT_SWAP.md)。

## Modem 启动（重要）

该板的 modem 启动时进入 DMS 工作模式 **`factory-test`** —— RF 禁用、无
网络注册。原厂 Android 从不会遇到这个问题，因为它自己的 init 序列会显式
设置该模式。

`/etc/init.d/uf896-modem-online`（START=60，先于 70 的 ModemManager）：

1. 最多等待 30 秒 `/dev/wwan0qmi0`，
2. 执行 `qmicli -d /dev/wwan0qmi0 -p --dms-set-operating-mode=online`，
3. 将 `uf896-modem-online` 记入 syslog。

如果 modem 始终不注册，请先检查 `logread | grep uf896`。

## A2 引脚 —— 已启用（r5 中更正）

与 HMUF02-V5、UZ801、UF02 和 HM-MIFIB-V12 一样，**UF896 设置
`qcom,a2-pin`**（补丁 `867`，板卡 DTS）。该保持使 modem 的 A2 电源域
持续被投票（`&bam_dmux` 上的 `pm_runtime_forbid()`），从而 AP 永远不会
释放它。

r4 发布时没有该引脚，假设是这个基带不会触发 A2 静默卡死问题。**那是错的。**
一台建立数据承载的现场设备在运行约 930 秒时中止：

```
qcom-q6v5-mss 4080000.remoteproc: fatal error received: a2_power.c:1216:A2 Assertion Failed
remoteproc remoteproc0: handling crash #2 in 4080000.remoteproc
```

随后每 70–130 秒崩溃循环一次（`a2_power.c:1216` 四次，然后
`a2_task.c:1185`）。行号与 HMU05 上看到的 `a2_power.c:1189` 不同，是因为
这是不同的 modem 固件构建；卡死问题本身是同一个。

旧的"经过现场测试、无断言"的说法来自一次在流量下运行时间不够长、没能
触发它的长时间测试。

## 我们需要的反馈

如果你有 UF896 v1.1，请反馈：

1. 镜像能否启动（串口控制台 / failsafe 是否可达）？
2. `uf896-modem-online` 是否把 modem 切换到 `online`？
3. modem 是否注册（`mmcli -m 0` 显示 `registered` + 运营商）？
4. 插在卡槽 2 的卡是否无需任何额外命令就能注册？
5. 在 A2 引脚启用的情况下（补丁 867 已启用），数小时数据流量后 `dmesg`
   中是否没有 `a2_power` / `a2_task` 断言？r4 发布时没有该引脚，在约
   930 秒时中止；我们希望确认该保持能让它保持安静。

请附上 `dmesg`、`logread` 和 `mmcli -m 0` 的输出开 issue。
